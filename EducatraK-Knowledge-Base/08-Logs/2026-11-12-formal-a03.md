# Formal A03 — Security, Authorization, and Privacy Audit

- **Timestamp:** Thursday, November 12, 2026 — 21:00:30 +08:00
- **State:** Accepted by owner; verification limits remain open.
- **Scope:** Read-only review of API routing/middleware, capabilities, object scope, authentication/session code, webhook validation, audit serializers, tests, and deployment configuration boundaries. No application behavior, production configuration, provider, database, migration, scheduler, worker, backup, or deployment operation ran.

## Validation

- Focused feature validation passed: **64 tests / 569 assertions** across authentication, staff administration, student access, audit-log reads, follow-up/webhook handling, notification reads, and cashier operations.
- Route and capability validation passed: **57 tests / 241 assertions**. Its route-wide assertion verifies every operational API route includes Sanctum authentication, active-user revalidation, first-login password-change protection, and a capability middleware.
- Official Laravel guidance was compared for Sanctum SPA/CSRF flow, authentication/session handling, error/debug configuration, and rate limiting. The implementation uses `statefulApi()`, `web` middleware, a regenerated session at login, session invalidation and CSRF-token regeneration at logout, and a five-attempt-per-minute login limiter.

## Findings

| Area | Result | Evidence / limitation |
| --- | --- | --- |
| Route-level authorization | Locally verified | All operational routes require `auth:sanctum`, active-user, password-change, and a named capability. The public Twilio callback is the intentional exception and has its own signature validation. |
| Role and privilege boundaries | Locally verified | Capability-map and feature coverage exercise all six roles for selected high-risk boundaries: user administration, audit/security events, settings, students, payments, close-outs, notifications, follow-up, reports, and imports. Super Admin has governance-only capabilities; regular Administrators cannot create/promote privileged roles; Accounting assignment remains closed. |
| Object-level scope / IDOR | Locally verified for implemented sensitive cases | Cashier payment list/detail/reprint/void paths limit access to payments recorded by that Cashier and return 404 for another Cashier's record. Void decisions are Accounting-only. High-risk staff-account protections and archive/restore safeguards are covered. This is not a live multi-user, deployed-database penetration test. |
| Sessions and login | Locally verified | Login regenerates the session; logout invalidates it and regenerates the CSRF token; inactive users with existing sessions are evicted; temporary-password users are restricted; session idle lifetime is 30 minutes; failed attempts are throttled at five per minute by normalized username/IP. The production limiter/cache backing and browser timeout journey are not verified. |
| CSRF | Code-reviewed; browser flow not verified | API routes use `web` middleware, `statefulApi()`, and default CSRF validation. Only the signed Twilio callback is exempted. No end-to-end browser run proved issuance of `/sanctum/csrf-cookie`, `X-XSRF-TOKEN` submission, and expected 419/401 expiry behavior. |
| Twilio callback | Locally verified | The callback requires a configured auth token, a constant-time matching Twilio signature, matching Account SID, SMS-reminder record, and matching provider message SID where present. Focused tests accept a correctly signed fictional callback and reject an invalid signature. Runtime credentials, public URL/proxy canonicalization, provider callback, and replay/load behavior remain unverified. |
| Error exposure | Partial | API requests are rendered as JSON and use Laravel validation/HTTP status responses. The repository default for `APP_DEBUG` is false, while the development example intentionally sets it true. Production error rendering, proxy behavior, and logs cannot be verified without the B13 target environment. |
| Audit and privacy redaction | Locally verified | Audit and security-event APIs serialize allowlisted scalar fields. Focused tests prove passwords and guardian-email data injected into audit snapshots are omitted, including nested values. Student/guardian, notification-recipient, and financial fields are limited to roles explicitly granted those workflows; notification recipients are intentionally available only to Cashier and Accounting. |
| Production transport/configuration | NOT VERIFIED | Target TLS termination, trusted proxy, CORS/stateful-domain settings, secure cookie/domain/SameSite values, production `APP_DEBUG`, secrets, and rate-limit backing store were not available. These are already controlled by B13's environment tracker. |
