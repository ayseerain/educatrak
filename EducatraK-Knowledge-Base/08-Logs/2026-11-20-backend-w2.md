## What changed
- `CreateBillingAccountAction`:
  - A shared `draft()` validates and computes without writing:
    - the student is enrolled and has a grade level;
    - the school year is current;
    - the plan is active (and therefore the latest version);
    - there is no existing account for the student and year;
    - exactly one active fee schedule exists for (year, grade);
    - removed fee items must be active, optional and in the schedule;
    - the kept total is at least 1;
    - installments are computed by `ComputeInstallmentScheduleAction`.
  - `create()` writes, in order: the account, `billing_account_items` snapshots, the installments, then `RecalculateBillingStatusAction`.
- `BillingAccountController::store` (`POST /api/billing-accounts`, 201):
  - the draft, create and `billing_account.created` audit run in one transaction with row locks;
  - a unique-constraint race maps to the same 422 duplicate message;
  - the response has the same shape as `GET /api/billing-accounts/{id}`.
- `BillingAccountController::preview` (`POST /api/billing-accounts/preview`) uses the same rules without writes. The M3.1 wizard needs it because Cashier lacks `settings.finance.view`.
- Both routes need `accounts.manage` (Cashier only).
- Existing payment, receipt, allocation and adjustment code is unchanged.
