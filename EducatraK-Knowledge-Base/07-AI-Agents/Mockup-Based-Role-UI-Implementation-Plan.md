## 2. Role-specific workspaces and shared paths

This is the implemented six-role workspace split. The capability source remains Project Specification Sections 6.4–6.5; the plan records user-facing destinations and explains the few shared paths. Unresolved policy in Decision 31.6 does not grant speculative capabilities.

- **Super Admin — governance:** governance dashboard; user administration for Administrators and non-privileged roles; security-event review; read-only financial/change audit. The protected bootstrap account cannot be changed, reset, or deactivated. No student, billing, payment, finance-setting, void, report, follow-up, notification, clearance, close-out, or backup-operation workspace.
- **Administrator — system control:** system dashboard; user administration for regular staff; system configuration; backup operations; security-event review. Cannot operate finance or student workflows and cannot create/promote Administrator or Super Admin accounts through ordinary administration.
- **Cashier — daily collection:** student and billing context for collection work; cash payment entry/history and receipts; own void-request status; combined follow-up and notification workspace; own daily close-out. Cannot approve voids, run standalone reports, manage finance/system settings or users, or review general audit history.
- **Accounting Officer — financial oversight:** payment review; finance policies; read-only system configuration; void approvals; close-out review/sign-off; financial reports and statements; combined follow-up and notification workspace. Cannot record payments, manage users, or enter the Auditor's Audit Review workspace.
- **Auditor — independent review:** dashboard and one read-only Audit Review workspace. No standalone operational, student, payment, report, notification, settings, or close-out pages.
- **Registrar — clearance:** amount-free, search-only student identity lookup for clearance and the clearance/permit destination. No general student directory/profile or financial workspaces.

**Shared paths with different role boundaries:** Dashboard and profile/password are common signed-in functions, with role-specific dashboard content. Administrator and Super Admin use the same user-administration page because both have a distinct staff-governance duty; server and UI rules give them different role choices and protect the bootstrap account. Cashier and Accounting share Follow-up & notifications because both use the same queue and reminder workflow; notification retry remains Cashier-only. Administrator security events and Super Admin/Auditor financial-change audit remain separate destinations.

A role's assigned destination does not imply that every workflow is production-ready. Screens whose API or policy is unresolved remain unavailable or fail closed as documented under U02–U08 and U11; no mock success state may stand in for a live operation.
