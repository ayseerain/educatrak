## Sequence after the backend contract passes

1. **Type the verified contract.** Add only backend-confirmed archive state, list scope and transition methods to `schoolStructureApi.ts`. Add report/account scope to their existing API clients after the backend tests prove values and role behavior. Keep snake_case request and camelCase response conventions already present. No invented field or placeholder action.
2. **School-year views — ADM-05.** Keep the current card layout and pagination. Add clearly labeled Active/Archived views using the existing `ViewTabs` pattern; default to Active and fetch the correct backend scope. In Active, show Archive only to Administrator on a non-current row. In Archived, show Restore and audited label correction to Administrator; show terms/exams read-only under their existing parent. Accounting sees both authorized views without write controls. A restored year returns as non-current; the user must separately use the existing reasoned Make current action. Do not expose year/term date editing while archived or imply date locks are removed.
3. **Section views — original ADM-07/ADM-08.** Keep the selected grade in component state while switching its Active/Archived section view; do not create per-grade routes or reset grade selection. Active includes unarchived active **and inactive** rows with distinct text badges. Archived contains only archived sections; preserve original section names/grade/IDs. Arrange one section per table row with a dedicated Actions cell and existing compact `TableActionGroup`/`TableActionButton` controls. Show Edit/Archive in Active and allowed rename/Restore in Archived only to Administrator. Accounting has read-only display. Do not equate `active=false` with Archived or silently reactivate an inactive section on restore.
4. **Confirm and report transitions.** Reuse the current Radix dialog pattern for Archive and Restore. Name the exact year/section, state that linked records remain, and explain the view/report consequence: ordinary reports exclude archived-year records/payments and their ordinary collection totals until restore; the Archived scope retains them. Use accessible names, keyboard focus, disabled pending states, server error text and success feedback. Never borrow staff-account 30-day anonymization copy. Do not use a button before the transition API is available.
5. **Existing financial pages.** Add an explicit ordinary/Archived scope within `/accounts`, `/reports/daily` and `/reports/outstanding` only after the backend contract is stable. Default ordinary scope excludes archived-year records. An Archived scope makes retained records discoverable to roles already authorized for that page: Cashier/Accounting account reads, Accounting reports; do not add report access to Cashier or financial settings access to Administrator. Preserve current/all-year account filters *within* the selected archive scope and label what “all” means. Keep student statement's current-year behavior unless separately approved. Avoid altering Payments, Dashboard, Close-out or Ledger Import screens under this scope.
6. **Rows, totals, CSV and print must agree.** Include selected scope in React Query keys, pagination requests, export page loops and print page loops; changing scope resets affected page selection, not selected grade. Daily report method/cashier totals and void rows must come from the same backend scope. Ordinary and Archived scope labels must appear in page headings/summary, CSV filename or header, and print document header so a dated report is not mistaken for an unfiltered historical total. Outstanding print's current “All school years” subtitle must be made scope-specific. Do not compute or reconcile monetary totals in the browser.
7. **Student context.** Preserve existing section name on students assigned to an archived section. If the backend returns a real archive state, show a truthful Archived badge where it helps explain why the option is unavailable; otherwise do not invent the badge or a history feature. Existing assignment remains editable only under backend-confirmed rules.
